# Weird 300

A travel blog of visits to the 300 places in *Weird Guide Britain* by Dave
Hamilton (Wild Things Publishing, 2026). Hosted on GitHub Pages at
https://tchingos.github.io/weird300/ from the `main` branch of
`tchingos/weird300`. GitHub Pages builds it with Jekyll; there is no local
Jekyll install, so the live build is the real test.

## Writing rules (apply to every word that ends up on the site)

- Never use em dashes or en dashes. Use a full stop, a colon, or a comma.
  `scripts/check.py` fails a page that contains one.
- Always use the Oxford comma: "Jillian, Emma, and I", not "Jillian, Emma
  and I".
- Do not join two complete sentences with "and". Write them as two
  sentences. "We stayed in Stornoway. We drove an hour south." not "We
  stayed in Stornoway, and we drove an hour south." Using "and" inside a
  sentence for a list or a pair ("rocks and ruins") is fine.
- Write in the first person as Tim Chingos ("I"). Only say "we" once the
  post has said who that is ("Jillian and I", "Barry and I"). Warm and plain,
  with contractions, not gushing.
- When Tim supplies his own text, keep it as written. Fix only clear typos.
- The `with` field names only the regulars (Jillian, Emma). Anyone else,
  however many, is `Friends`. Name them in the write-up instead.
- Only state facts Tim gave you or that are well established. Never invent
  details of the visit (birds seen, weather, who said what). Ask instead.
- Never copy text from the book. Credit it, and point readers to it.
- Do not end posts with a running count ("N down, M to go"); the home page
  already shows progress.
- Set `before_book: true` on a visit that happened before Tim had the book.
  The page then shows a short note saying so (`_includes/place-note.html`).

## Layout

| Path | What it is |
|---|---|
| `_places/<slug>.md` | One page per visit: YAML front matter plus the write-up. `visited` is the trip date; `published` is when the page went up (set automatically) |
| `_posts/YYYY-MM-DD-<slug>.md` | Journal posts: anything that is not one of the 300. Shown at `/journal/`, and never counted toward the 300. A post with a `location` name and `lat`/`lng` also gets a pin on the home map, in the journal's red (`--journal`) rather than the site accent. Leave the coordinates off and it simply isn't mapped |
| `assets/journal/<slug>/` | A journal post's photos |
| `assets/photos/<slug>/` | That visit's photos, `01.jpg` onward, each with a small copy in `thumbs/` for cards and the gallery. The first listed is the hero and card image; give it `focus: "50% 25%"` (any CSS object-position) when a centre crop would cut off the subject |
| `_data/categories.yml` | The book's seven sections; `category` must match one |
| `_data/home.yml` | Home page headline and optional hero photo |
| `_layouts/` | `default` (shell), `place` (one visit), `post` (one journal post) |
| `_includes/` | Components, one job each: `hero` (picks the landscape banner or the portrait side-by-side layout from the cover photo's `shape`), `gallery`, `card`, `place-card`, `post-card`, `post-nav`, `places-map`, `map-point`, `theme-toggle`, `analytics`, `photo`, `photo-url`, `place-facts`, `place-note`, `place-nav`, `progress`, `home-hero`, `site-header`, `site-footer` |
| `_sass/` | One partial per component, plus `_tokens.scss` for every colour and size. The dark palette is a mixin included twice there, once for a dark system and once for `[data-theme="dark"]`, which is what lets the header's light/dark switch override the system setting |
| `assets/icons/`, `favicon.ico` | The map-pin icon, generated by `scripts/make_icons.py` |
| `assets/js/map.js` | Draws any `places-map` include with Leaflet, and repaints the pins when the theme changes |
| `assets/js/theme.js` | The header's light/dark switch. Loaded synchronously in `<head>` so a saved choice applies before the first paint, and it remembers the choice in `localStorage` |
| `assets/js/lightbox.js` | Opens every `photo` include full-size, with arrows, keys and swipe |
| `scripts/weird300/` | Python package: `photos`, `exif`, `shapes`, `pages`, `checks`, `site`, `archive` |
| `scripts/new_visit.py`, `scripts/new_post.py`, `scripts/check.py`, `scripts/archive_originals.py` | Thin command-line entry points onto the package |
| `inbox/` | Git-ignored drop zone for raw photos. Nothing leaves it until the originals are archived |
| `originals/<slug>.yml` | What was archived for that visit: the archived filename, the `NN.jpg` it became on the site, size, checksum, and dimensions. Text, so it lives in git. The photos themselves never do |

New behaviour goes in a new include, partial, or module, not into an existing
file that already does something else. Photo paths are built only in
`_includes/photo-url.html`.

## Commands

```sh
uv run scripts/archive_originals.py "Place Name" inbox      # ALWAYS FIRST, see below
uv run scripts/new_visit.py "Place Name" inbox/<folder> --category "Rock Formations" --region "Town, County"
uv run scripts/new_visit.py "Place Name" more.jpg --add  # add photos to an existing page
uv run scripts/new_post.py "Post title" inbox --date 2026-10-06            # a journal post
uv run scripts/check.py                                # must pass before pushing
uv run scripts/rebuild_photos.py                       # only after changing the size budget
uv run scripts/import_photo.py assets/about inbox/x.jpg  # a photo for a page, not a place or post
```

`uv` pulls Pillow, pillow-heif and PyYAML on first run; nothing to install.

Photos must go through `new_visit.py` or `new_post.py`. They rotate photos
upright, convert their colour profile to sRGB (iPhone HDR and Display P3
photos look grey or dull otherwise), save a 1600px main copy and a 720px
thumbnail (the size budget in `weird300/renditions.py`, which keeps 300
places at about 480 MB, under GitHub Pages' 1 GB cap), strip all
metadata so no GPS data is published, and record each photo's `shape`
(`landscape` or `portrait`, see `weird300/shapes.py`). The cover photo's
shape picks the page's hero layout. `check.py` rejects any photo that still
carries metadata or whose recorded shape is wrong.

Never delete anything from `inbox/` until the post is published.

## The originals

The published copies are 1600px with their metadata stripped, which is right
for the web and no use for print. A photo book needs the originals, so they go
to Google Drive before anything shrinks them:

```sh
uv run scripts/archive_originals.py "Place Name" inbox            # add --dry-run to see the plan
```

It uploads through the `weird300` rclone remote as
`YYYY-MM-DD - Place Name - NN.jpg`, flat in one Drive folder so the archive
sorts by visit date. `NN` is the same number the photo gets on the site,
because both number them in the order `photos.find` returns. Every file is
checked against its checksum on the far side, and only then is
`originals/<slug>.yml` written.

**Nothing is deleted from `inbox/` until that manifest exists.** The manifest
is the gate, not anyone's memory.

The remote holds the Drive folder id, so it is never written down here: this
repo is public. If `rclone listremotes` does not list `weird300:`, set it up
once with `rclone config create weird300 drive scope=drive root_folder_id=<id>`,
which needs a browser and so has to be run by Tim.

The originals still carry GPS and capture dates, which is exactly what the
publish step strips out. Keep the Drive folder private.

## Visitor numbers

GitHub's traffic insights count the repo page on github.com, not this site, so
the site has its own counter. Set `goatcounter` in `_config.yml` to the site
code from https://www.goatcounter.com and the script loads; leave it unset and
no analytics load at all. It sets no cookies and collects no personal data,
so there is nothing to consent to.

The question worth answering is whether anyone outside the email list is
reading, so the links in a "new post" email carry `?ref=email`. Those visits
group under that label, and anything without it came from somewhere else.

To keep Tim's own visits out of the numbers, visit the site once with
`#toggle-goatcounter` on the end of the URL. That sets a flag in that
browser's local storage and the counter skips it from then on. It is per
browser and per device.

## Publishing

Commit and push to `main`; Pages rebuilds in about a minute. Confirm with
`gh api repos/tchingos/weird300/pages/builds/latest --jq .status`. The remote
URL carries the `tchingos` account, which is what the global pre-push guard
expects. Ask Tim before pushing a new or changed visit.

Two places in the book can share a name. `new_visit.py` refuses to touch an
existing page without `--add`, and `archive_originals.py` refuses to overwrite a
manifest that records different photos. When it is genuinely a different place,
give it its own `--slug`.

To add a visit end to end, use the `add-visit` skill.

## New-post emails

Tim tells close friends and family about new posts by email. After a post is
live, write the note to `emails/<slug>.txt` (git-ignored) and open it with
`python3 scripts/compose_email.py emails/<slug>.txt`, which pre-fills a Gmail
compose window with the subscribers in BCC. Never send; Tim proofreads and
sends. Do not draft through the Gmail connector: it turns every link into a
google.com redirect that shows readers a "Redirect Notice" page. The list is `~/.config/weird300/subscribers.txt`,
one address per line (optionally followed by `# Name`), kept outside this
public repo. Details are in step 8
of the `add-visit` skill.
